## Learned User Preferences

- Prefer gobds packet-level block/stall (claims, pickups, other hot actions) so work never reaches BDS Script API; extend claim proxy rather than adding BEH hot-path handlers for the same denial.
- Open PR review threads: fix the issue or reply why intentional, then resolve — do not leave a pile of unanswered CodeRabbit/review comments.
- Prefer published upstream/community gophertunnel (and dragonfly) pins over local `go.mod` `replace` forks when a pin covers the fix.

## Learned Workspace Facts

- Claim proxy loads policy from `policy/claim_policy.v1.json` and can deny claim-related actions before they hit BDS; floor-only Y deny is intentional (not a bug). Claim action volume is wildly skewed — ~25 `entity_interact`/`entity_hurt` per 4h session vs ~47M `render` actions — so do NOT widen claim entity filtering beyond decoration entities (`minecraft:armor_stand`, `minecraft:painting`) in `handler_inventory_transaction.go`: there is no measurable gain and filtering every non-player actor would block attacking pokémon and using NPCs/boats inside any claim. Optimize the `render`/floor-deny path instead, and measure it with Go benchmarks (`session/floor_deny_bench_test.go`: deny mask 5789 → 1669 ns/op, owner fast path 2.5 ns/op, batched metrics 420 → 2.3 ns/op, all zero-alloc).
- Traffic/metrics keys may use raw XUID as the ops identifier; do not "fix" that to a hashed form without an explicit product decision.
- bds-manager can build this repo from local source (`D:\bedrock-server\gobds`) into `bds-manager/gobds/gobds.exe` for the TESTING/Windows flow.
- gobds terminates resource-pack delivery: clients get packs from the proxy's config URL list (`DownloadResourcePack=false`), so BDS/world packs never reach clients. Load URL packs via `readURLPack()` in `gobds/user_config.go` (download + `resource.Read`), NOT `resource.ReadURL` — `ReadURL` records the source URL as the pack's `downloadURL`, which the gophertunnel listener advertises as `TexturePackInfo.DownloadURL`, making clients self-download over HTTPS. That CDN path only fires on a pack cache miss (same UUID, new version) and fails on GitHub release asset URLs: 302 redirect, plus `manifest.json` at the zip root — the client-side CDN loader requires it inside a subfolder (per `resource.ReadURL` docs), while server-side compilation (`resource.Read`/`ReadPath`) accepts the root layout → players stuck on "Loading resource packs" or a half-applied pack. Empty `DownloadURL` serves packs over RakNet chunks, matching the hub (dragonfly serves unpacked pack dirs, no DownloadURL).
- Hub/downstream pack version skew is routine: bds-manager's `ProxyManager.generateConfig` fetches the latest Forgejo pokebedrock-res release on every proxy start (schema-1 `packs.json` split stack, or one legacy mcpack when that asset is absent), while the hub only updates its pack on hub restart — pack delivery must tolerate the hub and downstream servers shipping different pack versions.
- `[[Resources.Packs]]` filters are AND-ed. `MinMemoryTier` 0 and an empty `Language` match every client; `3d` is `MinMemoryTier` 2 (lower tiers stay 2D). `texts-en_US` ships with an empty filter (everyone); other `texts-*` packs match the client language. Offers stay highest-priority first.
- Known packets always decode then re-Marshal through gophertunnel (no raw-byte forward), so `AddPlayer`/`PlayerList` are re-encoded even with no gobds handlers; a bad GT pin causes multi-player error-code `Block` kicks when another player enters view.
- On protocol 2168, sanitize forwarded `AddPlayer` with `BuildPlatform == 0` to `DeviceDedicated` (same as dragonfly#1382); BDS/other emitters can leave it zero and kick every viewer.
- `PlayerUpdateEntityOverrides` must Marshal as a byte-only type (PMMP shape); an extra `Varuint32` variant desyncs decode to garbage types (e.g. `14`) and spams dialer errors without kicking.
- Protocol 2193 / gophertunnel v1.62.0 (1.26.50): go.mod pins official `github.com/df-mc/dragonfly@d42ce23` (`feature/26.50`). `DimensionDefinition.Range` became `MinimumY` + `HeightRange`; gobds `dimensionRangeByID` maps max as `MinimumY + HeightRange`.
